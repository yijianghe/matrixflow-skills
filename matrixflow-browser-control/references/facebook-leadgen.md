# Facebook 种草发帖 SOP（2026-08-07 新增）

目标：用「种草」而不是「广告」的方式，让目标用户主动了解并试用 MatrixFlow 指纹浏览器。

## 一、什么是种草，什么算硬广

✅ 种草：第一人称真实体验 + 具体痛点 + 用了之后的变化 + 价值点 + 自然的引导。
❌ 硬广：口号式吹捧、夸大承诺（"全网第一""保证不封号"）、刷屏式发布、留联系方式诱导。

## 二、文案结构（四段式）

1. **痛点开场**（1-2 行）：直接说出目标用户正在经历的麻烦；
2. **转折**：偶然/朋友推荐发现了 MatrixFlow；
3. **变化与价值**：2-4 个具体功能点 + 自己的真实感受（数字、场景比形容词有力）；
4. **软引导**：官网链接，或"做这行的朋友可以试试"，不强迫。

## 三、可直接套用的模板

### 模板 A：多账号运营者（痛点型）
```
做矩阵运营这两年，最大的噩梦就是账号被关联：
- 浏览器指纹太像，两个号被判定成同一个人；
- 登错窗口，把 A 号的内容发到 B 号；
- 每次换号都要重新登录一遍。

后来朋友推荐我用 MatrixFlow 指纹浏览器，直接打开了新世界：
- 每个账号一个独立窗口：独立指纹、独立 Cookie、还能单独绑代理 IP；
- 关掉重开登录态还在，再也不用反复扫码；
- 窗口批量创建、批量打开，还有 API + AI 自动化，发帖、养号、评论都能交给 AI。

配图是我现在的窗口列表——一台电脑几十个号，互不干扰，清清楚楚。
做多账号运营的朋友真的可以试试：https://browser.lingjingxia.com
```

## 四、发布流程

1. 确认窗口已登录 Facebook；
2. 准备文案（用模板改角度，禁止连发同结构）；
3. 可选：截一张 MatrixFlow 应用主窗口图（多窗口列表最有说服力）；
4. `node scripts/fb-post.mjs <profileId> --text-file D:\fb-post.txt [--image D:\mf-app.png]`；
5. 发布后到主页确认可见范围与内容；
6. 记录发布历史（标题/时间/链接），下次换角度。

## 五、素材截图

最有说服力的三类图：
- **应用主窗口**：左侧环境列表 + 多个窗口（一眼看到"一窗一号"）；

## 六、合规与风控

- 遵守 Facebook 社区守则：不得发布虚假/欺诈内容，不得滥用自动化；
- 自动化发帖频率要低、文案要自然，避免触发风控；
- 不承诺"保证不封号"，不把指纹浏览器说成"外挂"；
- 每个账号独立窗口/指纹/代理，控制每日发帖量；
- 引用他人素材前确认版权，截图不要暴露客户隐私信息。
